OKD Installation Docs: AI Generation POC

Iterative skill training approach for automated documentation generation

The Problem

The OKD documentation team will no longer maintain installation docs. We need an automated, AI-driven pipeline that generates accurate user-facing documentation from source code changes alone.

No dedicated docs team Docs already outdated (FCOS→SCOS) Must scale across versions

Core Formula

Docs4.x = LLM(Docs4.x-1 + CodeDiff4.x-1 → 4.x + SKILL.md)
Previous version docs + multi-repo code changes + generation instructions = next version docs

Three Inputs Explained

Baseline

v4.x-1 Documentation

Previous version's installation section — ~880 AsciiDoc files covering all platforms (AWS, GCP, Azure, vSphere, bare metal, etc.)

Delta

Multi-Repo Code Diff

Structured diff summaries from 7 repos between release-4.x-1 and release-4.x branches. Captures new features, deprecations, and parameter changes.

Instructions

SKILL.md

A detailed instruction file teaching the LLM AsciiDoc conventions, OKD patterns, conditional blocks, and how to map code changes to doc updates.

Training Loop: 4.17 → 4.22

We iteratively refine SKILL.md by generating docs for known versions and comparing against existing human-written docs.

How SKILL.md Evolves

Each iteration teaches the skill file new patterns based on what the generated output got wrong.

Initial (before 4.17)
Base rules: AsciiDoc format, OKD conditionals, version attribute updates, parameter tables, include directives
After 4.17 iteration
+ Structural reorganization detection (directory renames, file prefix changes like ibmz- → ibm-z-)
+ Stub generation for entirely new features
After 4.18 iteration
+ Cross-repo feature correlation (MCO changes → install prereq updates)
+ Deprecation notice patterns
After 4.19 iteration
+ Stub generation triggers — when new platform needs full assembly scaffold vs. update to existing
After 4.20 iteration
+ Deprecation cascade rules — removing platform updates all cross-references
After 4.21 iteration
+ Parameter table formatting refinements — row format, description style consistency
After 4.22 iteration (production-ready)
+ Final tuning: section headers, include directives, conditional content precision
Ready for autonomous 4.23 generation

Bottom line: The ~8% gap (not derivable from code) always requires human review. The goal is automating the 92%+ mechanical work — not replacing technical writers entirely.
